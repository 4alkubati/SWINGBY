# LEDGER — the field contract

Source of truth: `docs/bugs/ledger.jsonl`, one JSON object per line, sorted by id.
Driven **only** through `python tools/bugctl.py`. Never hand-edit the jsonl.
`docs/bugs/LEDGER.md` is generated by `bugctl render` — never hand-edit that either.

## Fields

| Field | Contract |
|---|---|
| `id` | `SB-0001`, sequential, **never reused**. A retired id stays retired, or an old note about SB-0012 silently reattaches to a different bug. |
| `title` | One sentence naming the defect, not the area. "Accept creates two payments rows", not "payments issue". |
| `severity` | `blocker` / `broken` / `sloppy` / `polish`. Ladder in `SCAN.md`. |
| `area` | `mobile` `backend` `web` `db` `design` `infra` `docs` `marketing`. |
| `status` | See lifecycle below. |
| `files` | `path:line`, repeatable. Lines drift; the fingerprint ignores them deliberately. |
| `evidence` | The proof. What the code actually does, quoted. Say `NOT YET CONFIRMED IN CODE` when it is a suspicion. |
| `repro` | What a human does to see it. |
| `verify` | **The check that proves it fixed.** Required to file, required to close. |
| `fix_hint` | Suggested fix, one line. Not binding. |
| `screenshot` | Path under `~/brain/inbox/debugging/`. |
| `found` / `found_by` / `found_at_commit` | Provenance. |
| `verified_at` / `verified_commit` | Last re-verification. `null` means never — the staleness signal. |
| `closed` / `closed_commit` | When and where it was fixed. |
| `fingerprint` | sha1 of significant title words + file paths sans line numbers. Dedupe key. |
| `notes` | Dated append-only log. |

## Status lifecycle

```
                  ┌─────────────────────────────┐
  (file) ──> open ─┤ verified --result gone      ├──> stale
                  │ verified --result still-broken──> confirmed ──> fixed
                  └─────────────────────────────┘        (close --verified)
                          └──> wontfix   └──> dupe
```

- **`open`** — filed, not re-verified against current HEAD. Not dispatchable.
  Everything from a scan enters here. Everything from a screenshot **stays**
  here until someone finds the cause.
- **`confirmed`** — re-verified as still broken. The only status `bugctl next`
  will hand out. This gate is what stops work on already-fixed bugs.
- **`fixed`** — the fix landed *and* the verify step passed.
- **`stale`** — no longer reproduces. Kept forever; a stale finding that returns
  is the best regression signal in the system.
- **`wontfix`** — deliberate decision, requires a note saying why.
- **`dupe`** — same defect as another id.

## The two guards

`bugctl close` refuses when:

1. the finding has **no verify step** — it cannot be proven fixed, so it cannot
   be closed;
2. **`--verified` was not passed** — closing is an assertion that you ran the
   verify step and it passed.

`--force` overrides both. Using it should show up in a commit message.

## Dedupe

`bugctl add` and `bugctl import` refuse a finding whose fingerprint already
exists, and print the existing id and status. That is the mechanism that keeps
scan #4 from refiling scan #3's work.

The fingerprint deliberately **ignores line numbers** — including them would
break dedupe on exactly the reruns it exists for, since lines drift on every edit.

Before filing anything by hand:

```
python tools/bugctl.py check "duplicate payments row on accept"
```

It does a looser term-overlap match than the fingerprint and will catch reworded
duplicates the hash misses.

## Reading the ledger

```
python tools/bugctl.py stats                        # health, incl. uncloseable count
python tools/bugctl.py next                         # what to fix now
python tools/bugctl.py stale --days 14              # what nobody re-checked
python tools/bugctl.py list --severity blocker --status open confirmed
python tools/bugctl.py list --area mobile --grep language
python tools/bugctl.py show SB-0007
```

`list` marks findings with `!` when they have no verify step. Those are
uncloseable by construction — writing verify steps for them is high-value,
low-cost work.

## Migrating the old findings

`~/brain/inbox/SENTINEL-findings.md` holds ~40 findings in the right *shape*
(symptom, proof, fix) but with no ids, no status and no verify steps, and roughly
half are believed stale. Migrating it is one focused session:

1. Parse each `## [SEVERITY] [CLASS] Title` block into a finding object.
2. Map `[BLOCKER]`→`blocker`, `[BROKEN]`→`broken`, `[SLOPPY]`→`sloppy`.
3. The block's `Proof:` line becomes `evidence`, `Fix:` becomes `fix`.
4. **Write a verify step for each** — this is the actual work, and the reason it
   has not happened yet.
5. `bugctl import` the array, then run a full VERIFY pass over the imported ids.

Expect roughly half to come back `stale`. That is the point.
